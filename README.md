## Projects

Each project is a real analysis I have run in an operating role, rebuilt here as a
repeatable tool on synthetic data. Each has a runnable CLI, a
[Claude skill](https://docs.claude.com/en/docs/claude-code/skills) so the analysis can
be run and interpreted conversationally, and a Zapier recipe for putting it on a
schedule.

### [01 · GTM Segmentation & ICP Scoring](projects/01-gtm-segmentation-icp)
Segments 24 months of closed-won and closed-lost deals to find which verticals, company
sizes and lead sources actually convert, then scores open accounts A–D for routing.
Weights are derived from observed win-rate lift, not chosen by hand, and segments under
12 deals earn no credit.

> Found three regulated verticals producing **64% of won ARR from 37% of deal volume**,
> closing 8 days faster. Applied to 75 open accounts, half the list stopped consuming
> outbound capacity.

*Salesforce · HubSpot · Clay · Zapier*

### [02 · Monthly Revenue Reporting Pack](projects/02-revenue-reporting-pack)
The investor and leadership pack: ARR waterfall replayed from an event log, cohort-based
NRR and GRR, and a pipeline forecast risk-adjusted by stage win rate and a 90-day
activity decay.

> Took $16.7M of open pipeline to **$3.4M risk-adjusted** — coverage of 7.4x raw against
> 1.5x adjusted. The raw number would have let leadership plan headcount against pipeline
> that had stopped moving.

*Salesforce · Zuora · Slack · Tableau*

### [03 · Recruiting Funnel Ops](projects/03-recruiting-funnel-ops)
Stage conversion, time-to-hire against requisition targets, source efficiency measured
at onsite rather than application, and stalled-candidate nudges routed to whoever owes
the next action.

> Every stage median sat inside SLA while **52 individual candidates were past it**, 15
> by more than two weeks — and the next action on 44 of them sat with a recruiter, not
> a hiring manager.

*Lever · Slack · Zapier*

### [04 · AR & Collections Agent](projects/04-ar-collections-agent)
AR aging, DSO and delinquency, plus a dunning cadence with a four-tier escalation
ladder. Automates the cadence and refuses to automate the judgement: disputes, six-figure
balances and recently contacted accounts are held back for a person.

> **70% of the overdue balance sat with five accounts** — five conversations, not a
> company-wide payment terms review.

*Zuora · NetSuite · Gmail · Slack · Zapier*

## Running any of it

Everything is standard-library Python 3.8+. No install step, no dependencies.

```bash
git clone https://github.com/BonnieChen88/BonnieChen88.github.io.git
cd BonnieChen88.github.io

python3 projects/01-gtm-segmentation-icp/src/icp_engine.py analyze
python3 projects/02-revenue-reporting-pack/src/revenue_pack.py
python3 projects/03-recruiting-funnel-ops/src/funnel_ops.py report
python3 projects/04-ar-collections-agent/src/ar_agent.py aging
```

Committed `out/` directories hold sample results, so the output can be read without
running anything.

## Using the Claude skills

Each project ships a skill in `.claude/skills/`. Copy the ones you want into your own
`.claude/skills/` directory and Claude Code will pick them up:

```bash
cp -r projects/*/.claude/skills/* ~/.claude/skills/
```

The skills cover more than "run this script" — they carry the interpretation rules that
matter: never present raw pipeline coverage as a forecast, never report a stage median
without the count past SLA, never dun a disputed invoice.

## A note on the data

**Every dataset here is synthetic**, generated by
[`tools/make_sample_data.py`](tools/make_sample_data.py) from a fixed seed. No employer,
customer or candidate data appears anywhere in this repository. Regenerate it with:

```bash
python3 tools/make_sample_data.py
```

The distributions are deliberately shaped to contain the patterns the tools are built to
find, so the analyses have something real to work on.
