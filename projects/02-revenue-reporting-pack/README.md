# Monthly Revenue Reporting Pack

The monthly pack for investors and leadership was the same work every month: pull ARR
movement, rebuild the waterfall, recompute retention, sanity-check the pipeline, write
it up. Two days of it, and a fresh chance to make an arithmetic error every time.

So I stopped rebuilding it and wrote it down as a process instead — same inputs, same
method, same format, generated. The forecasting half came out of earlier work risk-
assessing professional-services deals above $2M, where the lesson was that a pipeline
number nobody has stress-tested is not a forecast, it is a hope with a dollar sign
in front of it.

Rebuilt here as a standalone tool running on synthetic data.

## What it produces

From two raw exports — an ARR event log and the open Salesforce pipeline — it writes:

- **`out/board_pack.md`** — the investor/leadership write-up: headline table, ARR
  waterfall, segment mix, forecast and forecast-health commentary
- **`out/revenue_metrics.json`** — the same figures as structured data for a Tableau
  extract or a dashboard
- **`out/slack_summary.json`** — Block Kit payload for the Monday leadership post
- **`out/pipeline_hygiene.csv`** — the flagged-deal list AEs are asked to clear

## The part that matters: risk-adjusted, not raw

Most pipeline reporting stops at "open pipeline" and a stage-weighted total. Both
flatter the forecast, because neither knows whether anyone has touched a deal since
last quarter.

Two adjustments run on top of every opportunity:

1. **Historical stage win rate, by segment.** Enterprise deals in Discovery convert at
   4%, not the 8% an SMB deal does. Using one blended rate hides the difference.
2. **A 90-day activity decay.** A deal with no activity decays linearly to a 10% floor
   over 90 days. A deal untouched for three months is not a forecast — it is a memory.

In the sample data those two rules take $16.68M of open pipeline to $4.61M
stage-weighted and then to **$3.43M risk-adjusted**. Coverage against the quarterly
target drops from a comfortable-looking **7.41x to 1.52x**. That gap is the entire
argument for reporting this way: the raw number would have let leadership plan
headcount against pipeline that was not moving.

The same pass flags the hygiene problems behind the gap — 91 of 140 opportunities
carry at least one — including deals sitting in Commit that are still in Discovery.

## Run it

```bash
python3 src/revenue_pack.py                          # defaults to 2026-06 on sample data
python3 src/revenue_pack.py --month 2026-03
python3 src/revenue_pack.py --next-quarter-target 3000000
```

No dependencies. Python 3.8+.

## Method notes

- **NRR and GRR are cohort-based.** Both measure the customers who had ARR twelve
  months ago, so new logos cannot inflate retention. GRR ignores expansion by
  construction — it is the floor, and the more honest number of the two.
- **The ARR waterfall is replayed from an event log**, not from a balance snapshot.
  New, expansion, contraction and churn always reconcile to the closing balance.
- **The next-quarter target defaults** to 1.25x the trailing quarterly new+expansion
  run rate. Pass the real board target with `--next-quarter-target`.
